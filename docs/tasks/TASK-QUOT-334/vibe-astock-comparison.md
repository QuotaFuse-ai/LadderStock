**未对齐 M-3（v2 新增，v3 已实机复现并验证修法）：连板柱图 x 轴刻度落在非整数位，标签成对重复**

- 根因（已定位到行）：`frontend/src/charts/Chart.tsx:178`
  `values: (_u, splits) => splits.map((value) => points[Math.round(value)]?.label ?? '')`
  —— 不给 x 轴指定 `range` / `splits` 时，uPlot 把 x 当连续量排刻度，间距可能小于 1（0.25 或 0.5），
  `Math.round` 便把相邻刻度映射到同一类别。
- v3 实机复现（headless Chrome + `uplot@1.6.32`，与仓内版本一致，脚本用完即删、未入库）：

  | 类别数 | 实际刻度 `splits` | 映射出的标签 |
  |---|---|---|
  | 5 | `0,0.25,…,4`（17 个） | `1板,1板,2板,2板,2板,2板,3板,3板,3板,3板,4板,4板,4板,4板,5板,5板,5板` |

  → 缺口不是「某个截图正好没拍好」，而是**只要类别数不是 5 的整数倍就必现**；天梯档位越多越明显。
- 期望（修法已验证，已跑通）：把 x 设为类别轴——`scales.x.range` 固定为 `[-0.5, N-1+0.5]`、
  `axes[0].splits` 返回 `data[0]`（即 `0..N-1`），刻度即整数、一柱一刻度。
  实测同一脚本改为上述配置后，5 / 6 / 8 类分别得到 5 / 6 / 8 个刻度，标签各出现一次且数量＝类别数。
  验收：暗 / 亮 + 1024 三档各回归一张天梯截图，截图里标签数＝档位数。
- 条款依据：PRD §5.4 要求三处图表「可读」；UI-SPEC §11.6 第 3 条约束轴标签字号与取色。
- 与 DEC-042 的关系：这是**类别轴映射缺陷修复**，不是重做图表布局、也不是新增图型，不受 §2.4 限制。

## 6. 「半成品」结论

用 PRD §1 的尺子：

- **首页**：v2 版式下四块主体齐全，不会再出现「一张卡恒 `—` + 一整块空态」的旧问题；
  但自选 / 持仓在真实态为空时整块空白（H-2）仍会被一眼看出「没做完」。修 H-2 即过线。
- **市场**：不会被问半成品。三图、双主题、分段空态、溯源行都在；但 M-3 的轴标签重复
  会被懂行的人一眼看出「图没画对」，比 M-1/M-2 更伤第一眼印象，建议同批修。
- **涨停样本**：当前会被问。演示态 6 行 + 半屏空白，且与首页 / 市场的 47 家对不上；
  补完 L-1 消除第一眼问题，L-2 决定它是否只是「一张表」。
- **总体**：**现状不建议直接发群**。完成 H-2 + L-1 + M-3 三个最小改动后，三屏可达到「不是半成品」的第一眼标准；
  H-3 是规范收口、H-4 是口径待定，M-1 / M-2 / L-2 / L-3 属深度补齐，进入下一批。
