# DEC-042 UI 精修路线：走 A 方案（自有 token 深化），不引入第三方 UI 库 / webfont / 动画库

- 日期：2026-11-01
- 提出：人类（老板）「现在 ui 感觉还是有点粗糙，能不能商业化页面 ui 点，精致点」（QUOT-305）
- 裁决：人类于 2026-11-01 在 QUOT-305 回复「a」，选定 A；总经理落档
- 状态：生效
- 编号说明：原预占 DEC-040。DEC-040 已由 QUOT-308（UI-SPEC 覆盖扩至 18 屏 + 过渡时长裁定）预占，本单（纯文档、未合并、由裁决人本人持有）让号至 DEC-042。过渡时长 120ms/180ms 例外的**结论口径以 QUOT-308 落盘的 DEC-040 为准**，本单只定路线，不重复定数值。
- 关联：DEC-006（数据与资产只落本机、离线可用）、DEC-041（只做 LadderStock）、QUOT-306（执行单）、
  `docs/UI-SPEC.md` §0/§7/§11/§12.3、`frontend/tokens.json` v2.0.0

## 1. 背景

老板觉得前端页面粗糙。实测根因不是 token 体系不行，是**规范覆盖面和执行**：

- `docs/UI-SPEC.md` §0 只覆盖复盘 / 盯盘 / 验证 / 日志四屏，产品已有 18 屏，后加的 14 屏没有视觉基线与验收条目；
- `frontend/src/components/ui/index.ts:35` 导出的 `DataTable` 全仓零引用，数据页面各自手写行列，`PoolScreen.tsx` 还留着裸 `<table>`；
- §12.3「设计还原度按 §11 逐条走查」对新页面没有执行机制。

当时摆着三条路：A 自有 token 深化（约 1 周、可逆）、A+B 再做数据可视化观感（+3–4 天）、
C 换设计语言整页重写（2–4 周、不可逆、会作废 QUOT-300/302/304 的既有前端排期与现 UI-SPEC）。

## 2. 决定

1. **走 A**：在现有 `tokens.json` v2.0.0 上做页面级工艺精修——信息层级、留白与密度节奏、
   数字对齐基线、四态（加载骨架 / 空 / 降级 / 正常）统一、24–160ms 过渡且尊重 `prefers-reduced-motion`。
2. **C 不采用，且不是"以后也不做"**：本轮不做换设计语言。若将来要上 C，必须**由人类重新点名对标产品并重新立项**，
   同时接受 QUOT-300/302/304 已排的前端工作与本文覆盖的 UI-SPEC 章节重来一次。
3. **不新增 npm 依赖、不引 CDN 与外部字体/图标/动画库**。理由：产品只在回环地址离线运行，
   DEC-006 的边界是数据与资产只落本机；外部 webfont 会同时打破离线可用与隐私边界。
   视觉需求用已有 `lucide-react` + token 体系解决。确实缺刻度就**加 token**，不加 `p-[13px]` 这类任意值补丁。
4. **B 未授权**：图表只做「取色与主题统一、网格线弱化」这类 token 层调整，**不重做图表布局、不新增图型**。
   要升级到 B 需要人类另行批准。
5. **规范补齐是精修的一部分，不是附加题**：`docs/UI-SPEC.md` §0 覆盖范围扩到全 18 屏，§11 逐屏补验收条目，
   §12.3 的走查从"四屏"变成"全 18 屏"。每张屏交付 before/after 截图（暗 + 亮，1440×900）入 `docs/screenshots/`。

## 3. 边界与冲突处置

精修单（QUOT-306）**不改 `frontend/src/components/Layout.tsx` 的 `NAV_SECTIONS` 分组结构**——
QUOT-300（补已交付路由入口）与 QUOT-304（我的股票导航分组）正在改同一文件，
排序为 300 → 304 → 306 的外壳部分；306 的 14 张页面本体可与 300/304 并行。
不改任何数据链路与接口契约。
