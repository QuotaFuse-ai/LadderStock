# DEC-064: 持仓收益率——TWR / 资金加权 / 净值序列的取数口径与接口

日期：2026-11-06 ｜ 状态：待复核（GM） ｜ 关联：QUOT-433（本单）、
DEC-056（持仓账本 / 交易流水重放）、DEC-028（不拿成本价顶替现价）、
参考实现 `desktop/src/verticals/finance/lib/perfView.ts`

编号取值：开工时扫 `docs/decisions/`，最大号为 `DEC-063`，本决策取 `DEC-064`。

## 1. 问题

账本已经能按流水重放出「现在持有多少、成本多少」（QUOT-430 / DEC-056），
但**这段时间赚了多少**还答不上来。参考产品用两个收益口径回答：

- **时间加权（TWR）**：把每天的涨跌幅连乘，剔除加仓 / 减仓的时点影响，
  看「选的这些票本身走得怎么样」；
- **资金加权（MWR / XIRR）**：把每笔投入、取出和期末市值当现金流求内部收益率，
  看「这些钱实际赚了多少」。

两者不能互相替代，也不能拿区间数冒充年化。本决策钉死后端怎么算、缺数据怎么说。

## 2. 决定

### 2.1 逐日重建持仓市值（只读本机 `daily_k`）

- 对每个交易日 `t`：`MV_t = Σ 持有股数(t) × 收盘价(t)`。
- 持有股数按流水重放得出；同日先送转，其余按录入顺序（与 `core.portfolio.replay` 同一条）。
- **停牌日**（该票当天没有行）：按**最近一个收盘价**估值。这是「按最新可得价格持仓」，
  不是插值、不是补价、也不拿成本价顶替。
- **本地日线没覆盖到的票整只排除**：`excluded` 写明原因，`gaps` 逐条列出；
  组内其余持仓照常计算。不补价、不补 0。
- 判定「覆盖」的条件：该票最早一个收盘价不晚于它的首笔流水日期。
  晚于首笔流水就排除——「不拿后来的价格倒推买入当天的市值」。
- 流水日期晚于本地日线最后一根 K 线：这些流水**没算进本次收益率**，
  在 `warnings` 里写明笔数与日线末日，不按最后一根 K 线硬估。

### 2.2 TWR

```
r_t = (MV_t + 分红_t − MV_{t−1} − CF_t) / MV_{t−1}
twr_index_t = twr_index_{t−1} × (1 + r_t),  twr_index_0 = 1
```

- `CF_t` = 当天净申购：买入为正（钱进来）、卖出为负（钱出去）；
- **分红算收益**（进入分子），不算外部现金流；
- 前一交易日没有市值（空仓）时当天不计收益，指数不动；
- `twr = twr_index_last − 1`；
- 不足 2 个交易日的组不给序列（`series = null`），TWR 记 0；
- `twr_annualized` 只在 `span_days ≥ 365` 时给：
  `twr_index^(365/span_days) − 1`。

### 2.3 资金加权

- 现金流：每笔买入 / 期初持仓 = 流出（负），卖出与分红 = 流入（正），
  期末市值 = 最后一笔流入；
- 用一个标准库二分求年化 IRR：`Σ CF_k / (1 + r)^(days_k/365) = 0`，不引第三方；
- `mwr_period = (1 + irr)^(span_days/365) − 1`（区间收益）；
- **`span_days < 365` 时 `xirr = null`**，不拿区间数冒充年化；
- 现金流没有正负号（求不出根）时 `mwr_period = null`，不硬凑一个数。

### 2.4 金额字段

| 字段 | 来源 |
|---|---|
| `invested` | 期初持仓成本 + 买入金额（含买入费用） |
| `proceeds` | 卖出金额（已扣卖出费用） |
| `dividends` | 现金分红合计 |
| `fees` | 买入 + 卖出费用合计 |
| `end_value` | 最后一个交易日市值 |
| `gain` | `end_value + proceeds + dividends − invested` |

全部来自流水与估值，不重算第二套；分红不改持仓成本。

### 2.5 分组

本期只有一组：`market="A股"`、`currency="CNY"`、`label="人民币 · A 股"`。
不做汇率换算、不跨币种相加。B 股（900 / 200 开头）与外币流水由
`core.portfolio.trade_problem()` 挡进 `skipped`，不进任何金额。

### 2.6 接口

`GET /api/portfolio/perf?days=365`

- 复用 `_positions_guard`：回环 + `Host` 白名单，平面 JSON、`Cache-Control: no-store`；
- 只读本机 `daily_k`（一次 DuckDB 只读查询），不联网、不落盘、不调用模型；
- 流水为空 → `groups=[]` + `notes` 说明，**200 不报 500**；
- 服务端不做长缓存；查询参数 `days` 缺省 365，`0` = 全历史，非法值 422；
- **`days` 只裁剪走势序列**（`series.dates`），收益指标与 `start / end / span_days`
  始终按全部流水计算——否则「年化」会被默认的 365 天窗口截断成永远为 null；
- 响应顶层只有 `as_of / groups / skipped / gaps / sources / notes`，
  避开 `PRIVATE_KEYS`（`holdings` / `positions` / `trades` 等）。

字段形状对齐 `perfView.ts`：组级 23 个键（含 `series: {dates, twr_index}`），
缺失值一律 `null`，不补 0。

## 3. 手算对照（脱敏样例）

### 3.1 买入后部分卖出（跨一年）

| 日期 | 流水 | 价格 | 持有 | 市值 |
|---|---|---|---|---|
| 2025-01-02 | 买入 100 股 @10，费用 0 | 10 | 100 | 1000 |
| 2025-07-02 | 卖出 50 股 @12，费用 0 | 12 | 50 | 600 |
| 2026-01-02 | — | 14 | 50 | 700 |

- TWR：`(600 − 1000 + 600)/1000 = 0`，`700/600 − 1 = 16.67%` → `1.2 × 1.1667 − 1 = 40%`；
- 价格路径 `10 → 12 → 14` 也是 +40%，减仓那 600 不影响 TWR；
- MWR：`−1000 @t0、+600 @t181、+700 @t365`，解 NPV=0 得年化 **41.47%**，
  `span_days = 365`，所以 `xirr = mwr_period = 41.47%`；
- 金额：投入 1000、卖出所得 600、期末市值 700、盈亏 300。

### 3.2 中途加仓

| 日期 | 流水 | 价格 | 持有 | 市值 |
|---|---|---|---|---|
| 2025-01-02 | 买入 100 股 @10 | 10 | 100 | 1000 |
| 2025-01-06 | 买入 100 股 @12 | 12 | 200 | 2400 |
| 2025-01-07 | — | 13 | 200 | 2600 |

- 逐日收益：`+10%`、`(2400 − 1100 − 1200)/1100 = +9.09%`、`+8.33%` → TWR `30%`；
- 若把加仓的 1200 当收益，会算成 `(2600 − 2200)/2200 = +18.2%`——这就是 TWR 要剔除的部分；
- `span_days = 5 < 365` → `xirr = null`，只给区间数。

## 4. 代价与已知边界

- 逐日估值需要整段本地日线；没有 `ldst sync --dataset daily_k` 的用户只会拿到
  `ok=false` + 原因，不会得到编出来的收益率。
- 交易流水很少且跨年时，`series` 的点就是流水日 + 日线日，不是逐自然日补齐
  （没有交易与价格的日子不新增点）。
- 期初持仓（`opening`）没有现金流，它的成本计入 `invested`、也是 TWR 的起点市值；
  这是「把接手时的持仓当作起点」的口径。
