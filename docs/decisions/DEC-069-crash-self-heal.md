# DEC-069: 崩溃自愈执行口径（QUOT-491 / 482-C）

日期：2026-11-09
关联：QUOT-489（482-A 未落地）、QUOT-490（482-B 未落地）、QUOT-492（482-D）、QUOT-484（前端面板）
状态：已定稿

## 背景

QUOT-482 要求托盘侧具备「崩溃自愈」。482-A（账本 + 顺序启停引擎）两次运行失败未产出代码，482-B（adapters）未落地。482-C 不能等——需要在无 482-A/482-B 的前提下交付可用的自愈，且不得重复实现它们的职责。

## 决策

1. **崩溃识别以「主动停标记」为准（D4 执行口径）**：账本条目 `stopping_by_user=true` 才算主动关；无标记的进程消失一律视为崩溃进入自愈。主动停不重拉、健康置 `stopped`（对外折叠为 `ok`，无病态）。
2. **退避与上限**：等待序列 5s→15s→45s；5 分钟滑动窗口内最多 3 次重拉；超限停止重拉、置 `needs_human`、通知「需人工处理」；`POST /api/supervisor/state/{module}/reset` 人工解除。不许写无上限日志——每模块日志滚动只留最近 200 行。
3. **重拉通道用命令表过渡**：`data/supervisor/restart-commands.json`（argv、`shell=False`、内容全部来自部署侧）。表空如实报「无可用重拉通道」并照常走退避——**绝不假装重拉成功**。482-B 落地后换 `Restarter` 实现，引擎不动。
4. **账本最小承载**：482-A 缺位期间由 `supervisor/ledger.py` 只存自愈必需字段（pid / 停止标记 / 计数 / 窗口 / 健康），落盘 `data/supervisor/ledger.json` 原子写；`origin` / `cmdline_hash` 只透传不判定。482-A 落地后字段超集平替。
5. **通知只报失败**：失败 / 放弃弹 Windows Toast + 本地滚动事件日志（200 行）；恢复不弹（不制造噪音）；任一通知通道抛错只记一行日志、全吞，**通知模块挂掉不影响自愈主流程**；不借通知引入托盘驻留（D6）。
6. **发起 ≠ 恢复**：重拉发起只置 `restarting`，下轮巡检确认新 pid 存活才回 `ok`；等待期间进程自行恢复则不重复拉起（防双实例）。

## 后果

- 482-C 现在即可交付，482-A/482-B 落地时以超集平替账本、以 adapters 平替命令表，接口不变。
- 主动停依赖标记落盘；若宿主被强杀（连标记进程一起死）会被当崩溃重拉——这是有意为之（宿主强杀后模块本就无人管）。
- 对外 `/api/supervisor/state` 仅回环，写面（reset）需来源证据，与控制面同一套闸门函数，不新增鉴权体系。
