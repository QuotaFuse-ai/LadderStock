# DEC-045 DEC / UI-SPEC 变更记录的编号与合并顺序

- 日期：2026-11-02
- 提出：总经理（QUOT-317，2026-11-01 撞号事故收口）
- 状态：生效
- 关联：DEC-039（两份实体）、DEC-040（预占 + 回填）、DEC-041、DEC-042、
  `docs/decisions/`、`docs/UI-SPEC.md` 变更记录、QUOT-308、QUOT-317

## 1. 背景

2026-11-01 一天内 DEC 编号撞了两次：`DEC-039` 一度有两份实体；`DEC-040` 一份实体 + 一份预占。
原因是编号只写在单描述里、实体文件落在不同分支，两边互相看不见；`docs/UI-SPEC.md`
的变更记录行也在同一天被 3 条 PR 同时改动，合并时互相覆盖。

## 2. 决定

1. **编号只在开单时预占**，取值方式固定：
   `git ls-tree -r --name-only origin/main docs/decisions/` → 取最大号 +1。
   单描述里必须落一行「已扫到的最大号 = NNN」，作为取值当时的可复核快照。
   不按「我见过的最后一个」或本地分支上的号取值。
2. **回填让号必须写裁定来源**。历史上让出的空位（例：2026-11-01 main 上是 039/041/042，
   040 由总经理裁定回填给 QUOT-308，后续新单从 DEC-043 起）必须在单或 DEC 里写明
   谁裁定、给哪张单。没有裁定来源的空号视为未占用，不得默认沿用。
3. **未合并分支上的 DEC 不算已占用**；但让号成本由**零反向引用**的一方承担。
   若同批 spec 已引用某编号，优先保留原号并在合并说明里标注引用方。
4. **`docs/UI-SPEC.md` 变更记录行是第三个撞车点**：同一天多条 PR 会改同一行/同一段。
   合并顺序上串行处理；内容合并成一条，不按 PR 各留一行重复描述。
5. 本决策只约束流程，不改任何产品代码与接口契约。

## 3. 影响

- 开单人多一步 `git ls-tree` 扫描；换来的是编号唯一、可追溯。
- 合并冲突从「编号实体二选一」降级为「变更记录行合并」，冲突面收敛。
- QUOT-317 的检查脚本与验收报告按本决策执行；后续单沿用。
