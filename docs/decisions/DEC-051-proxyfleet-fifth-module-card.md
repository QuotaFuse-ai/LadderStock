# DEC-051 ProxyFleet 作为第 5 个模块卡片展示（同一「子模块」列表）

- 日期：2026-11-04
- 状态：已采纳
- 关联：DEC-047（端口归属）、DEC-050（工具组件）、QUOT-391

## 背景

DEC-050 把 ProxyFleet 放在「子模块」下方独立的「工具组件」区，仍是 4 张模块卡 + 1 张组件卡。
老板在 QUOT-391 明确要求「做成 5 个模块」，即代理池应与四个数据模块并列展示。

## 决定

1. 设置页「子模块」列表合并为 5 张卡片：TickHub-CN、TickHub-US、Wire、StockSenate、ProxyFleet；
   页头计数与端口表都按 5 个模块展示。
2. ProxyFleet **仍不登记为 peer**（`PEERS` 不变），继续使用只读 `COMPONENTS` 模型；
   这样数据集归属校验不会被代理池污染（沿用 DEC-050 第 1 条）。
3. 代理模块的生命周期仍由 Windows 计划任务 `ProxyFleet` / `pfctl.py` 托管；卡片只提供
   状态、端口与「打开控制台」，不提供 pip 安装、启动、停止按钮。

## 代价

- 5 张卡片的操作能力不完全相同：4 个数据模块可安装/启停，代理模块只读。这是有意的边界，
  卡片上的「代理模块」徽标与托管说明负责解释差异。
