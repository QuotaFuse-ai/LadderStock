# DEC-083：产物面进页——日志写面、研究首次起跑、盯盘自检、收盘对账接线（QUOT-561）

日期：2026-11-12
关联：QUOT-561（拆自 QUOT-519）、DEC-082（零 CLI 面）、DEC-065（持仓账本回环写面口径）、
DEC-052 / DEC-055（自选读写面）、DEC-058（提醒收件箱）、QUOT-558（S5 健康弹窗）、§5.6（不回落演示）
状态：已定稿

## 背景

QUOT-559 已经让**读**全部进页（自动补齐 + 零命令文案），但五张产物面仍只有命令行一条路：
交易日志「记一笔」、AI 复盘五段、AI 周报、收盘对账、研究段落。同时站内还留着 7 颗永久
disabled 的死按钮（日志页记录一笔、验证页运行收盘对账、盯盘页通知链路自检、设置页静态 peer 的
安装 / 启动 / 查看日志）。结果是：读得进来，写不出去——普通用户永远看不到自己的产物长什么样。

本单把「写」补齐：每一张产物面要么有页内写入口，要么有页内自动触发；每颗死按钮要么接真动作，
要么删掉并给出白话替代。

红线（派单正文，逐条保留）：不前端重算指标 / 硬造产物（QUOT-500）；不编数；缺失如实；
不改 frontend/src 迁就测试（不删断言 / 不用 `expect(true)`）；不 sleep 掩盖偶发；禁止整文件 skip；
不动 `backend/` 与 CI workflow（需要新端点走正常契约，本单补最小端点）；不硬编码模型清单；
密钥不进前端 / 日志 / 提交；不动 5950/8000/9100/9000 端口；真失败走 S5 弹窗，不回落演示；
所有入口零 CLI、白话文案，无死按钮、无命令指引。

## 决策

1. **交易日志开最小写面 `POST /api/journal/trades`（后端 `web/journal_write.py`）**：
   - 落库复用 `journal.log.add_trade()`——CLI 与 HTTP **同一个函数、同一张 `journal.sqlite`**，
     HTTP 层不重算、不派生、不聚合；
   - 闸门复用既有实现：回环 + `Host` 白名单 + 写来源证据（同源 `Origin` 或
     `X-LDST-Client: 1`），接 `web/radar.py::privacy_write_guard`，**不新增鉴权机制**；
   - 请求体**白名单硬拒绝**：多一个键就 400（券商账号 / 资金密码这类字段根本没有入口）；
     `note` 上限 200 字；
   - 响应扁平 + `no-store` + 只回这一笔（字段严格等于 `journal.log.TRADE_FIELDS`），
     聚合仍只走 `GET /api/journal/stats`；
   - 另开只读探测 `GET /api/journal/write-info`（只回开关与写入路径、**不触发写入**、
     不带写头），日志页据此决定「记一笔」是否可用。
2. **日志页写路径走 `TradeEntryDrawer`，写成功后静默重取统计**：抽屉提交后只
   `refresh()`（`useAsync` 的 auto 通道，数据在时不清屏），**不整页 `reload()`**。
   理由：`reload()` 会把页面打回骨架屏，抽屉（portal）随之卸载，用户刚看到的
   「已记到本机」确认条一闪就没——这是本单实测出的真实 UX 缺陷，不是测试口径问题。
   失败照后端 detail 原样说（「没有记上」+ 原因），不当作成功、不回落演示。
3. **研究页首次起跑进页**：`/research/:code/report` 在「还没有任何研究记录」空态给出
   「开始研究」，走既有 `POST /api/research/{code}/run`（`only=report` 从第一段跑起）+ 
   `GET /api/research/jobs/{id}` 轮询，段结果照后端产物渲染；详情页空态给
   「去报告页开始研究」深链。后端 404 文案去掉 CLI 命令串（保留「还没有任何研究记录」
   等语义标记，`classify404` 不受影响），本机研究产出仍由后端算，前端不硬造段落。
4. **盯盘「通知链路自检」接控制面 `notify`**：提交 `POST /api/control/commands/notify`
   并轮询任务；**送达与否只看后端日志事实**（「通知已送达本机渠道」/「通知没有送达：
   渠道不可用或后端缺失」），前端不把「任务成功」当成「送达成功」。
5. **验证页「运行收盘对账」接控制面 `validate`**：15:00 前禁用并给出原因（收盘行情未定版），
   15:00 后可提交；任务结束后只重新读取 `GET /api/validation`，**逐条判定仍由后端给出**，
   前端不重算、不补算历史。修正原空态分支反转：15:00 前展示的是「去写明日条件」，
   15:00 后才是「运行收盘对账」（此前正好写反，前半天给了一颗被闸门挡住的按钮、
   后半天反而没有入口）。
6. **删死按钮，不做假替代**：设置页静态 peer 卡片的安装 / 启动 / 查看日志三颗按钮删除——
   静态 peer 的定义就是不参与进程管理，这三件事在本产品里不该由用户点；卡片改为只陈述
   「静态 peer 无需安装或启停」的事实。日志 / 验证 / 盯盘三屏的按钮按 2–5 条接线。
7. **所有新入口共用一个 hook `lib/usePageCommandRun.ts`**（控制面提交 + 1.5s 轮询 +
   `PARTIAL_MARKER` 降级识别 + 409 白话文案），三屏同一套行为，避免各写一遍再漂移。
   演示态永不触发真实任务（按钮禁用 + 原因「演示样本不触发真实任务」）。

## 后果

- 五张产物面全部可在页内落地：日志（写面）、复盘五段 / 周报（读已有产物 + 页内触发已由
  QUOT-559 的自动面覆盖）、收盘对账（`validate`）、研究段落（首次起跑）。
- 站内零死按钮：7 颗永久 disabled 全部接线或删除；出现的新失败一律白话 + S5。
- 交易日志仍然「隐私只进本机」：写面回环独占 + 写来源证据 + 白名单字段，MCP 侧依旧无任何
  journal 工具（本决策不放宽 MCP 的禁止旁路）。
- 新增测试：`frontend/tests/quot-561-wiring.test.tsx`（5 例：日志写成功 / 写失败原样说 /
  通知未送达 / 通知送达 / 对账提交后重读）、`frontend/tests/api-headers.test.ts` 补写面头断言、
  `frontend/tests/research-pages.test.tsx` 补首次起跑 3 例、后端
  `tests/unit/web/test_journal_write_endpoint.py` 与 `tests/unit/web/test_research_first_run.py`。
- 规范回改：`docs/UI-SPEC.md` 的「交易日志不经 HTTP」与「对账按钮」两条按本决策补注口径
  （只加注、不改原文结论），`docs/MCP_TOOLS.md` 的「`/api/*` 全部为 GET」按写面落地补注。
